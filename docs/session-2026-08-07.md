## Relay/ngrok reality check (2026-08-06/07)

`relay/README.md` was quietly wrong: it documented reserving a static
ngrok domain as a free-tier feature. As of 2026-08, custom/reserved
domains require a paid ngrok plan (`ERR_NGROK_313` on the free tier).
However, every free ngrok account still gets one **auto-assigned "dev
domain"** (e.g. `launch-shredder-careless.ngrok-free.dev`) that's
permanently tied to the account and stays fixed across restarts — so the
practical workflow (one stable URL to share with the party) still holds,
it's just not a chosen name anymore. `relay/README.md` corrected to
describe this accurately. Other real gotchas hit and resolved this
session, worth knowing before the next live session:

- `relay/node_modules` isn't committed (correctly gitignored) and won't
  exist on a fresh checkout or if it's been cleaned — `npm install` in
  `relay/` before `npm start` if `Cannot find module 'ws'` shows up.
- ngrok's free-tier interstitial warning page can block the WebSocket
  handshake for a browser that hasn't visited the tunnel's `https://` URL
  directly yet. Each participant needs to open the `https://` URL once in
  their own browser and click through before connecting from the site —
  this is per-browser, not per-account.
- An "upgrade required" message when connecting is almost always a
  `ws://` vs. `wss://` typo — the tunnel is HTTPS-only.
